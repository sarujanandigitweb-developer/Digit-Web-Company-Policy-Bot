1. Project Overview

"Ask the Digit" is DigitWeb's internal company-policy assistant. It has three user-facing capabilities and an admin console:

  1. Public department chatbot (/): a staff member asks a policy question; the answer is generated by an LLM grounded in retrieved chunks of uploaded policy documents (hybrid vector + trigram search in Postgres/pgvector), restricted to the chosen department plus "Shared" departments. General questions go to Shared knowledge only. Unanswerable questions are recorded as Knowledge Gaps.
  2. Document Library (/library, built 2026-09-18 and enhanced 2026-09-21): a tree of Platform / Model / Section / Method / Document read from a Google Sheet; the user opens a Google Drive/Docs document and asks questions about that single document. The whole document is put in the prompt (no chunking or embeddings).
  3. Admin console (/admin/*): users, departments, knowledge documents upload/processing, a Knowledge Library (folders/resources) with per-resource chat, search playground, analytics, conversations, knowledge gaps, settings, and a password reset flow (/forgot-password).

Stack: TanStack Start (Vite/React 19, file-based routes in src/routes), Nitro (preset vercel), Tailwind 4, shadcn/ui, Vercel AI SDK (ai 5.0.99), Neon Postgres (@neondatabase/serverless), Neon Auth (Better Auth) for identity, nodemailer for reset-code email. The repo was generated by and is still linked to Lovable (AGENTS.md, .lovable/, vite.config.ts uses @lovable.dev/vite-tanstack-config).

6. Current Workflow / Architecture

Three separate answer paths that deliberately share nothing beyond the AI gateway:

  1. Public chat (/api/chat): intent routing (intent.server.ts//api/chat.intent) decides general vs department-specific. General: Shared-only retrieval. Department-specific with none chosen: UI asks the user to pick a department (Shared/system departments excluded); choice is kept for the conversation. Retrieval (retrieval.service.ts) blends vector and trigram scores over only active documents, scope = selected department + is_shared departments (no silent global fallback). Best score below CONFIDENCE_FLOOR (0.5) records a knowledge gap. Messages, citations and provider logs are stored; users can give feedback.
  2. Admin Knowledge Library (/admin/library, /api/admin/library.*): folders/resources in Postgres, per-resource chat via resource-chat.server.ts; refusal sentence "I couldn't find that information in this resource."
  3. Document Library (/library): auth required (requireAuth). Tree from Sheet (cached 10 min server, 5 min browser) -> user opens a node -> /api/library/document/:id returns the reading copy -> /api/library/ask re-resolves the node id server-side on every call (single-document isolation is structural) and puts the whole document (max 96,000 chars) in the prompt. Text cached in drive_document_cache, validated by Drive modifiedTime (trusted 60 s) or a 30 min TTL when unavailable. Refusal sentence "I couldn't find that information in this document." only when the info is genuinely absent. Images cannot be seen; [Screenshot N] markers give position only.

AI gateway: walks the provider chain, skipping providers without keys; falls back on rate limit, timeout, network, 5xx; a provider with no first content within 20 s, or a stream ending in abort, counts as failure; HTTP 400/422 stops the chain. Qwen is the last-resort backstop.

Roles: super_admin (everything), admin (team-leader powers + create/edit team leaders), team_leader (knowledge, gaps, analytics, conversations; per-department documents). Auth is Neon Auth JWT/session verified in session.server.ts.

Retention rule: conversations whose chat_sessions.started_at is older than 7 days (DB clock) are deleted with their messages, citations and feedback in one transaction with a system audit entry (audit_logs.record_id = 'conversation-retention', actor_id NULL). Knowledge gaps and provider logs survive (FK set NULL).

Prerequisites: Node (version not documented) or Bun, a filled .env (copy .env.example; at least one AI provider key, DATABASE_URL, DATABASE_URL_UNPOOLED, NEON_AUTH_URL, VITE_NEON_AUTH_URL, SMTP for reset email).

cd /home/led-247/Digit-Web-Company-Policy-Bot
npm install            # or: bun install
npm run dev            # Vite dev server (dev port typically 8080, as used by scripts/token.sh)
npm run build          # production build (Nitro vercel preset -> .vercel/output)
npm run lint
npx tsc --noEmit       # type check (passes at HEAD)
node --test tests/conversation-retention.test.mjs

First admin: ./scripts/bootstrap-admin.sh <email> '<password>' '<name>' (registers in Neon Auth and inserts the profile; only way to create the first super admin). Admin API token for curl: ./scripts/token.sh <email> <password> (about 15 min). Reset-service account: ./scripts/setup-auth-service.sh.

Local dev does not run the Vercel cron; call the endpoint manually with Authorization: Bearer <CRON_SECRET> using a secure client.
